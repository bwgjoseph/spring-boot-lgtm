# Grafana: Visualization & Alerting Requirements

## 1. Role & Responsibility (The "Job")
Grafana is the **Visualization & Alerting Hub** for the production cluster. Its "job" is to provide a single, unified interface for all observability data, serving as the central point for dashboarding, incident management, and alerting.

## 2. High Availability
- **Replica Count:** Single replica (baseline), designed to scale to 3+ for HA.
- **State Storage:** Must use an external, HA-capable database (PostgreSQL) for user state. SQLite is strictly prohibited to ensure state survival during pod restarts.

## 3. Visualization Standards
- **Correlation:** Every dashboard must support "drill-down" capabilities (e.g., jump from Mimir Metric spike -> Tempo Trace -> Loki Log line).
- **Service Graphs:** Must render dependency maps generated by Tempo's Metrics Generator.

## 4. Alerting
- **Channel:** Alerting must be centralized via **Alertmanager**, routing all notifications to Mattermost.
- **Reliability:** Alerting rules must use `absent()` to detect missing metrics, ensuring alerts fire even when services are completely down.
